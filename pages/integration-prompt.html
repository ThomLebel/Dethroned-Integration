Prompt d'intégration

Prompt à donner à Claude pour adapter n'importe quel contenu existant — outil interactif, visualiseur, documentation — en une nouvelle page autonome du site.

Architecture du site — Le site est multi-fichiers. index.html est le shell global (CSS, navigation, moteur). Chaque page est un fragment HTML dans pages/ID.html, chargé à la demande. Les <script> et les <style> dans les fragments fonctionnent normalement — aucune modification de index.html n'est nécessaire pour ajouter une page.

════════════════════════════════════════
ARCHITECTURE DU SITE
════════════════════════════════════════

Structure de fichiers :
  index.html       ← Shell (CSS global, navigation, JS core) — NE PAS MODIFIER
  nav.json         ← Arbre de navigation — seule modification nécessaire
  pages/ID.html    ← Fragments de page — à créer

Chaque page est un fragment HTML sans <html>/<head>/<body>,
injecté dynamiquement dans #page-container.

Après injection, index.html appelle automatiquement :
  - runPageScripts()   → réexécute tous les <script> du fragment
  - applyPageLayout()  → active la pleine largeur si data-fullwidth="true"

CONSÉQUENCE : les pages sont 100% autonomes. Aucune modification
de index.html n'est jamais nécessaire pour ajouter une nouvelle page.

STRUCTURE D'UN FRAGMENT — OUTIL INTERACTIF (pleine largeur + JS)
════════════════════════════════════════

Fichier : pages/mon-outil.html

<!-- data-fullwidth="true" sur la racine = pleine largeur automatique -->
<div data-fullwidth="true">

  <div class="page-hero">...</div>

  <div class="callout callout-or">...mode d'emploi...</div>

  <!-- Styles locaux — préfixe les sélecteurs pour éviter les conflits -->
  <style>
    #mo-root { display: grid; ... }
    .mo-panel { background: var(--noir2); ... }
    /* Utiliser les variables CSS du site, jamais de valeurs hardcodées */
  </style>

  <!-- HTML de l'outil -->
  <div id="mo-root">
    <!-- Utiliser des IDs préfixés (ex: "mo-") pour éviter les conflits -->
    <select id="mo-select">...</select>
    <canvas id="mo-canvas"></canvas>
  </div>

  <div class="sources">...</div>

</div><!-- /data-fullwidth -->

<!--
  RÈGLES POUR LE JAVASCRIPT :
  1. Tout le JS dans une IIFE (function() { ... })() pour éviter
     la pollution de scope global entre les pages.
  2. Préfixer toutes les fonctions et variables locales.
  3. Utiliser uniquement document.getElementById() — pas de sélecteurs
     globaux qui pourraient toucher d'autres pages encore en cache.
  4. Les event listeners sur document/window doivent être propres :
     éviter d'en ajouter plusieurs si la page est visitée plusieurs fois.
  5. window.registerSearchEntries() appeler à la fin du script.
-->
<script>
(function() {
  'use strict';

  // Toutes les variables et fonctions ici sont locales à cette page.

  function g(id) { return document.getElementById(id); }

  // ... logique de l'outil ...

  // Enregistrement dans la recherche — toujours en dernier
  if (typeof window.registerSearchEntries === 'function') {
    window.registerSearchEntries([
      { title: 'Mon Outil', page: 'mon-outil', section: 'Outils', content: 'mots-clés' },
    ]);
  }

  // Initialisation
  init();
})();
</script>

ENTRÉE nav.json À AJOUTER
════════════════════════════════════════

Dans la section appropriée de nav.json :
{
  "id": "mon-sujet",    ← nom du fichier sans .html
  "icon": "🎮",
  "label": "Mon sujet"
}

Si la section n'existe pas encore, ajouter un bloc :
{
  "section": "Ma Section",
  "items": [
    { "id": "mon-sujet", "icon": "🎮", "label": "Mon sujet" }
  ]
}

════════════════════════════════════════
CONSIGNES DE LIVRAISON
════════════════════════════════════════

Livrer :
  A. Le fichier pages/mon-sujet.html complet et autonome
  B. L'entrée nav.json à ajouter (section + item)

NE PAS livrer de modifications à index.html — ce n'est jamais nécessaire.

Pour les outils avec beaucoup de JS : utiliser une IIFE,
préfixer tous les IDs HTML et les variables JS, ne jamais
utiliser de noms génériques (ex: "canvas", "btn") qui
pourraient entrer en conflit avec d'autres pages.

Pour les styles : toujours utiliser les variables CSS du site
(--or, --noir2, --vert, etc.) plutôt que des valeurs hardcodées,
et préfixer les sélecteurs CSS pour les limiter à l'outil.
