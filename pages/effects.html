Effets & EffectBehaviour

~100 effets (+ 14 légendaires) assemblés depuis ~25 blocs stateless. Chaque effet est une EffectData.tres avec une liste ordonnée de behaviours. Le pipeline ctx circule de bloc en bloc.

~25 blocs 8 familles 14 légendaires 5 niveaux de complexité
Règle cardinale : les EffectBehaviour lisent les managers depuis ctx — jamais en statique. CombatManager est l'unique point d'injection du ctx initial. Les effets sont purs : aucune condition dans un effet — les conditions appartiennent aux déclencheurs.

Le pipeline EffectRunner

GDScript — effect_runner.gd
static func execute(effect_data: EffectData, ctx: Dictionary) -> void:
    var c = ctx.duplicate()
    for behaviour in effect_data.behaviours:
        if c.get("pipeline_stopped", false):
            break
        c = behaviour.apply(c, effect_data)
    # VFX et Audio notifiés APRÈS le pipeline complet — jamais pendant
    VFXManager.on_effect_executed(c)
    AudioManager.on_effect_executed(c)

États élémentaires : ApplyElementalState est le seul bloc qui appelle la résolution de synergies. Après chaque application d'état, il vérifie la table de synergies dans StatusManager et déclenche l'effet automatique si une paire est détectée. Le déclencheur Avancé "Synergie Élémentaire" est ensuite notifié via process_event("elemental_synergy", ctx).

Exemple — ApplyElementalState (nouveau v4)

GDScript — apply_elemental_state.gd
extends EffectBehaviour

func apply(ctx: Dictionary, data: EffectData) -> Dictionary:
    var target = ctx.get("target")
    if not target: return ctx
    var state_id: String = data.get("elemental_state", "")  # ex: "chauffe"
    var sm = ctx["status_manager"]
    var synergy = sm.apply_elemental(target, state_id)
    # synergy = { triggered: bool, type: String, effect: ... }
    if synergy.triggered:
        ctx["elemental_synergy"] = synergy
        ctx["is_elemental_state"] = true
        # Notifie TriggerRunner pour "Synergie Élémentaire" (DA avancé)
        ctx["skill_manager"].process_event("elemental_synergy", ctx)
    return ctx

Exemple — ApplyDirectDamage

GDScript — apply_direct_damage.gd
extends EffectBehaviour

func apply(ctx: Dictionary, data: EffectData) -> Dictionary:
    var target = ctx.get("target")
    var dmg    = ctx.get("damage", 0.0)
    if target and dmg > 0:
        # Manager depuis ctx — jamais get_node() ou statique
        ctx["health_manager"].take_damage(target, dmg, data.tags)
        # VFXManager notifié après le pipeline complet, pas ici
    return ctx

Règles de conception — checklist

  • Effets purs : aucune condition dans un effet. Toute phrase "si", "quand", "lorsque" → appartient au déclencheur.
  • C1 en lecture seule : les effets #degat_direct ne réécrivent pas l'ACC — ils ajoutent ou modulent via ctx["damage"].
  • États vs DoT distincts : un état élémentaire (Chauffé, Intoxiqué…) n'inflige pas de dégâts. Un DoT n'applique pas d'état élémentaire sauf mention explicite.
  • Marques permanentes : disparaissent uniquement à la mort de la cible ou au remplacement. Une seule marque active à la fois.
  • Atténuation boss/mini-boss : stun/immobilisation ×0,3 · états élémentaires ×0,5 · déplacements forcés ×0,4 · chaos comportemental ×0,4.
  • Nouveau behaviour si et seulement si : réutilisable par ≥ 3 effets distincts ET non exprimable en configurant un bloc existant.
