Ajouter du contenu

Procédures pour étendre le système sans modifier l'existant. Chaque type de contenu a son propre flux d'ajout.

Principe : ajouter = créer des fichiers. Ne jamais modifier les fichiers de base existants sauf si la règle ci-dessous l'exige explicitement.

Ajouter un nouveau déclencheur

Règle : créer un .tres suffit. Aucun code existant n'est modifié sauf si le type d'événement est nouveau.
  • Créer res://skills/data/triggers/DB-XXX_nom.tres de type TriggerData
  • Renseigner event_ids, loc_type, cooldown, tags
  • Assembler les conditions depuis la bibliothèque dans l'inspecteur
  • Si le type d'événement est nouveau : ajouter process_event("nouveau_type", ctx) dans le manager source + enrichissement dans ContextBuilder

Ajouter un nouvel effet

  • Créer res://skills/data/effects/FAMILLE/E-XX-YY_nom.tres de type EffectData
  • Assembler les behaviours depuis la bibliothèque dans l'inspecteur
  • Si un nouveau behaviour est nécessaire : créer res://skills/behaviours/CATEGORIE/nom_behaviour.gd qui étend EffectBehaviour

Ajouter un nouveau manager

  • Déterminer la couche (N) selon les responsabilités et les dépendances
  • Copier le template template_manager.gd
  • Déclarer en Autoload dans l'ordre de sa couche (voir page Intégration Godot)
  • Documenter les méthodes publiques et les managers appelés

Ajouter un nouvel ennemi

  • Créer EnemyData.tres avec stats, type IA, compétences
  • Utiliser la scène enemy_base.tscn — pas de nouvelle scène sauf cas exceptionnel
  • Les 3 méthodes hors-contrat propres à EnemyBase sont héritées automatiquement
  • Passer par EnemyManager.spawn(data) — ne jamais instancier directement

Ajouter une page à ce guide

  • Créer pages/mon-sujet.html — fragment HTML avec registerSearchEntries()
  • Éditer nav.json — ou utiliser l'éditeur ✏️ Nav dans la sidebar
  • Tester en local avec python3 -m http.server 8080

Pour les outils existants (Arena Forge, équilibreur…), utiliser le Prompt d'intégration →
