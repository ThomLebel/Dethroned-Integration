Communication entre systèmes

Quatre patterns de communication couvrent tous les cas du Manager Graph. Choisir le bon pattern évite la majorité des bugs d'architecture.

Appel direct Blackboard EventBus résiduel Propriété observable
Règle décisionnelle : si tu dois chercher dans le code qui écoute un signal, c'est que tu aurais dû faire un appel direct.

Les 4 patterns

1. Appel direct

A doit appeler B avec un résultat immédiat attendu. C'est le pattern par défaut pour tout flux critique du gameplay. La callstack est complète, l'ordre est garanti, les bugs sont traçables.

GDScript — appel direct
# CombatManager appelle SkillManager après chaque collision
# → résultat immédiat, callstack traçable
func resolve_hit(initiator: Node, receiver: Node) -> void:
    var ctx = _build_ctx(initiator, receiver)
    SkillManager.process_hit(ctx)         # appel direct
    BulletTimeManager.on_kill(receiver)   # appel direct

Quand l'utiliser : toujours, sauf si l'une des trois conditions suivantes s'applique.

2. Propriété observable (Blackboard)

B veut lire l'état de A à un instant T sans qu'A sache que B existe. Au lieu d'émettre un signal à chaque changement, A expose une propriété ou un dictionnaire que B lit quand il en a besoin.

GDScript — lecture directe via interface entité
# TriggerCondition lit ctx["target_hp_ratio"] directement
# → pas de signal, pas d'abonnement, lecture au moment T
func check(ctx: Dictionary, data: TriggerData) -> bool:
    return ctx.get("target_hp_ratio", 1.0) <= data.threshold_value

# Le ctx est enrichi par SkillManager avant d'être passé :
ctx["target_hp_ratio"] = receiver.get_hp_ratio()  # via interface entité

Quand l'utiliser : quand les données changent fréquemment (vitesse, PV) et que le lecteur n'a besoin de la valeur qu'à un moment précis, pas en continu.

3. EventBus résiduel (broadcast)

Un événement ponctuel intéresse N systèmes indépendants de présentation (Audio, VFX, UI). Ces systèmes ne modifient jamais l'état du jeu — ils réagissent juste pour jouer un son ou afficher un effet.

Règle absolue : l'EventBus ne transporte jamais de logique de gameplay. Si un récepteur modifie l'état du jeu en réponse à un signal, ce signal doit devenir un appel direct.

wall_hitPhysicsManagerAudioManager, RunMetricsCollectorSynchrone

GDScript — signal Godot légitime
# HealthManager notifie la Couche 4 après avoir traité la mort
# → HealthManager a déjà fait son travail (appel direct EnemyManager)
# → le signal informe Audio + Encyclopedia, sans retour d'état
func _process_death(entity: Node) -> void:
    EnemyManager.on_enemy_dead(entity)      # appel direct — critique
    EventBus.enemy_died.emit(entity, "damage")  # signal — secondaire

4. Callback enregistré

Un système a besoin d'être notifié d'un événement futur précis sur une entité précise, sans s'abonner à un broadcast global. Utilisé principalement par StatusManager.on_expiry() et SkillManager._active_observers.

GDScript — callback ciblé dans StatusManager
# PropagateOnExpiry enregistre un callback dans StatusManager
# → déclenché uniquement à l'expiration de CE statut sur CETTE cible
# → pas de signal global, pas d'abonnement EventBus
func apply(ctx: Dictionary, data: EffectData) -> Dictionary:
    ctx["status_manager"].on_expiry(
        ctx["target"],
        data.id,
        func(expired_target: Node):
            var neighbors = ctx["physics_manager"].query_radius(
                expired_target.get_position(),
                data.get("propagation_radius", 120.0),
                "enemies")
            for n in neighbors:
                ctx["status_manager"].apply(n, data.id, data.duration, data.dot_damage)
    )
    return ctx

Checklist avant d'émettre un signal

  • Qui sont exactement les 1 à N récepteurs ? Si je dois chercher dans le code → appel direct.
  • Ce signal modifie-t-il l'état du jeu ? Si oui → appel direct obligatoire.
  • Ce signal est-il émis plus de ~10×/seconde ? Si oui → propriété observable.
  • Les récepteurs sont-ils tous en Couche 4 ? Si non → reconsidérer.
  • L'événement est-il futur et ciblé sur une entité précise ? Si oui → callback enregistré.
