Déclencheurs

75 déclencheurs (45 De Base + 30 Avancés) assemblés depuis ~20 blocs TriggerCondition. Chaque déclencheur est une TriggerData.tres — aucun code par déclencheur.

45 De Base 30 Avancés ~20 blocs
Principe : un déclencheur ne va jamais chercher l'information lui-même. Tout lui arrive dans le ctx enrichi par CombatManager + SkillManager. Les conditions lisent ctx, elles ne font pas de get_node().

Les deux pools

PoolCompteRègle fondamentalePeut être Set de Base ?
Déclencheurs de Base45Gameplay brut uniquement — mouvement, tir, timer, collision physique, état brut des ennemis. Aucune condition issue d'un effet ou d'un passif de classe.✅ Oui
Déclencheurs Avancés30Réagissent obligatoirement à ce que le kit du joueur génère (buff, DoT, invocation, état élémentaire…). Doivent partager ≥1 tag avec le build existant.❌ Non

TriggerRunner — évaluation dans le Manager Graph

Architecture v2 : le TriggerRunner ne s'abonne plus aux signaux EventBus. C'est CombatManager qui appelle SkillManager.process_event(type, ctx) directement après chaque événement physique. Le ctx arrive déjà enrichi.
GDScript — trigger_runner.gd (sous-système SkillManager)
# Appelé par SkillManager.process_event() — jamais en autonome
class_name TriggerRunner

func evaluate_all(event_type: String, ctx: Dictionary, build: Array[SkillSlot]) -> Array[SkillSlot]:
    var fired: Array[SkillSlot] = []
    for slot in build:
        var trigger = slot.trigger_data
        if not event_type in trigger.event_ids: continue
        if not _cooldown_ok(trigger, ctx): continue
        if _all_conditions_pass(trigger, ctx):
            fired.append(slot)
            _update_cooldown(trigger, ctx)
    return fired

func _all_conditions_pass(trigger: TriggerData, ctx: Dictionary) -> bool:
    for condition in trigger.conditions:
        if not condition.check(ctx, trigger): return false
    return true

Enchaînement Rapide (3 conditions)

TriggerData.tres — Enchaînement Rapide
TriggerData {
    id: "DB-COL-09"   trigger_type: "base"
    event_ids: ["enemy_hit"]
    loc_type: "loc_cible"   time_window: 0.5
    tags: ["#collision", "#sequence", "#trajectoire"]
    conditions: [
        CheckTargetDifference {},         # cible ≠ précédente
        CheckTimeSince {                   # dernier hit < 0,5s
            event_key: "last_enemy_hit_time",
            time_window: 0.5
        },
        RecordTimestamp {                  # met à jour (toujours vrai)
            event_key: "last_enemy_hit_time"
        }
    ]
}

Règles de décision

SituationDécision
Seuil numérique dans ctxCheckThresholdAbove/Below/Between avec ctx_key configuré
Flag booléen dans ctxCheckBoolFlag avec flag_key
État sur la cibleCheckTargetTag ou CheckTargetStatus
État élémentaire actif sur la cibleCheckTargetStatus { check_any_elemental: true }
Compatibilité Déclencheur AvancéCheckBuildTag { required_tag } en dernière condition
Temps depuis un événementCheckTimeSince + RecordTimestamp en fin
N occurrencesIncrementTriggerCounter + CheckCounter
Continuité temporelle (X secondes)CheckContinuousState
Condition unique → nouvelle TriggerCondition ?Uniquement si réutilisable par ≥ 3 déclencheurs distincts

Ordre d'implémentation recommandé

  • Sprint 1 — Infrastructure : TriggerCondition, TriggerData, TriggerRunner, TriggerStateComponent
  • Sprint 2 — Blocs de base : CheckThresholdAbove/Below/Between, CheckBoolFlag, CheckTimeSince/Without
  • Sprint 3 — Compteurs & séquences : IncrementTriggerCounter, CheckCounter, CheckCounterInWindow, RecordTimestamp
  • Sprint 4 — Cibles & build : CheckTargetTag, CheckTargetStatus, CheckTargetCount, CheckTargetDifference, CheckPlayerTag, CheckBuildTag
  • Sprint 5 — .tres De Base communs : créer les 45 TriggerData De Base (commencer par les Communs)
  • Sprint 6 — Avancés : CheckDotStackCount, CheckAlliedCount, CheckContinuousState, CheckSequenceOrder puis les 30 Avancés
