Flux d'un événement de jeu

De la collision physique à l'exécution d'un effet — comment l'information circule entre CombatManager, SkillManager, TriggerRunner et EffectRunner.

Résumé : CombatManager construit le paquet brut. SkillManager l'enrichit de façon systématique et fixe. TriggerRunner distribue le paquet final sans le modifier. Les déclencheurs lisent, ils ne cherchent pas.

Le dictionnaire ctx — Blackboard complet

Le ctx est enrichi couche par couche. CombatManager fournit les données physiques. SkillManager ajoute les données de contexte. Les blocs lisent et écrivent dans le ctx sans jamais appeler get_node().

GDScript — ctx type enemy_hit (complet)
{
    # ── Données physiques (CombatManager)
    "event_type":        "enemy_hit",
    "initiator":         bille,        # Node entité initiateur
    "receiver":          fennec,       # Node entité receveur
    "position":          Vector3(12,0,-4),
    "speed":             340.0,
    "acc_damage":        28.5,         # vitesse × masse × coeff_ACC

    # ── Enrichissement SkillManager (via interface entité)
    "timestamp":         142.34,
    "target_hp_ratio":   0.85,
    "target_has_dot":    false,
    "target_tags":       ["#ennemi", "#normal"],
    "build_tags":        ["#collision", "#dot"],
    "trigger_state":     trigger_state,  # carnet de bord

    # ── Managers injectés (utilisés par les behaviours)
    "health_manager":    HealthManager,
    "status_manager":    StatusManager,
    "pool_manager":      PoolManager,
    "physics_manager":   PhysicsManager,

    # ── Enrichi par le pipeline d'effets
    "damage":            0.0,          # modifié par ComputeBaseDamage
    "pipeline_stopped":  false,
    "knockback_applied": false,        # posé par ApplyKnockback
}

Symétrie initiateur/receveur

resolve_hit ne type jamais ses paramètres. L'interface commune garantit que les mêmes méthodes sont disponibles quelle que soit la combinaison.
